# SRP Methods Library

Complete catalog of Structure, Reasoning, and Presentation methods available in the
SRP-CCC framework. All methods correspond to validated combinations in
`01_Areas/SAGE_Methodology/srp_combinations.csv` (4,779 combinations, verified 2026-06-12).

Read this file when you need to select specific methods. The SKILL.md contains quick
heuristic tables for common cases — come here for the full picture.

## 1. Structure Methods

How you decompose and frame the problem before reasoning begins.

### Systems & Complexity (S1–S10)
Use when the problem involves interconnected parts, feedback loops, or emergent behavior.

| ID | Method | When to use |
|----|--------|-------------|
| S1 | DSRP (Distinctions, Systems, Relationships, Perspectives) | Need to see a problem from multiple angles; good default for complex conceptual problems |
| S2 | Soft Systems Methodology | Messy human/organizational situations where the "problem" itself is contested |
| S3 | System Dynamics | Feedback loops, delays, and accumulation matter; behavior-over-time questions |
| S4 | Viable System Model | Organizational design; asking whether a system can survive and adapt |
| S5 | Critical Systems Thinking | Power dynamics and marginalized perspectives matter in the framing |
| S6 | Systemic Design | Need to design an intervention into a complex system, not just analyze it |
| S7 | Hierarchy Analysis | Problem has clear levels/layers that need to be mapped (org charts, taxonomies, dependencies) |
| S8 | Complex Systems Analysis | Emergence, nonlinearity, phase transitions; when simple cause-effect breaks down |
| S9 | Complex Adaptive Systems | Agents adapting to each other; markets, ecosystems, social dynamics |
| S10 | Self-Organized Criticality | Systems that build tension then release suddenly; looking for tipping points |

### Strategic & Business (S11–S16)
Use when the problem is strategic, competitive, or organizational.

| ID | Method | When to use |
|----|--------|-------------|
| S11 | SWOT Analysis | Quick strategic snapshot; strengths/weaknesses/opportunities/threats |
| S12 | Porter's Five Forces | Competitive dynamics in an industry or market |
| S13 | Value Chain Analysis | Understanding where value is created and captured in a process |
| S14 | PESTLE Analysis | External environment scan (Political, Economic, Social, Tech, Legal, Environmental) |
| S15 | Business Model Canvas | How a venture creates, delivers, and captures value |
| S16 | Stakeholder Mapping | Who's affected, who has power, who has interest, where are the conflicts |

### Visual & Relational (S17–S22)
Use when seeing relationships, flows, or patterns visually would help decomposition.

| ID | Method | When to use |
|----|--------|-------------|
| S17 | Causal Loop Diagrams | Mapping reinforcing and balancing feedback loops |
| S18 | Stock-Flow Diagrams | Tracking accumulations and rates of change |
| S19 | Network Analysis | Relationships between nodes matter more than individual nodes |
| S20 | Systems Archetypes | Recognizing common patterns (fixes that fail, shifting the burden, etc.) |
| S21 | IBIS (Issue-Based Information System) | Argumentative structure; mapping issues, positions, and arguments |
| S22 | Rich Pictures | Messy situations that benefit from informal visual mapping before formal analysis |

### Problem Framing (S23–S27)
Use when the problem definition itself is uncertain or contested.

| ID | Method | When to use |
|----|--------|-------------|
| S23 | Boundary Critique | The boundaries of the problem are themselves controversial; what's included/excluded matters |
| S24 | Leverage Points | Looking for where a small intervention creates large systemic change |
| S25 | Problem Framing Canvas | Ill-defined problem that needs structured unpacking before any analysis |
| S26 | Taxonomy | Need to classify, categorize, or create a typology before reasoning |
| S27 | Conceptual Modeling | Building an abstract model of a domain to reason about it |

## 2. Reasoning Methods

How you actually think, infer, test, and decide.

### Formal Reasoning (R1–R3)
Classical logic-based approaches.

| ID | Method | When to use |
|----|--------|-------------|
| R1 | Deductive Reasoning | Premises are well-established; need to derive certain conclusions |
| R2 | Inductive Reasoning | Building generalizations from observations or patterns |
| R3 | Abductive Reasoning | Finding the best explanation for a surprising or incomplete observation |

### Problem-Solving Frameworks (R4–R8)
Structured approaches to finding and fixing problems.

| ID | Method | When to use |
|----|--------|-------------|
| R4 | Root Cause Analysis | Something went wrong and you need to find why, not just what |
| R5 | A3 Problem Solving | Structured single-page problem analysis (Toyota-style) |
| R6 | 8D Problem Solving | Team-based structured problem solving with containment actions |
| R7 | TRIZ | Need inventive solutions; overcoming technical contradictions |
| R8 | Design Thinking | Human-centered problem with empathy, ideation, and prototyping phases |

### Decision Cycles (R9–R11)
Iterative decision-making loops.

| ID | Method | When to use |
|----|--------|-------------|
| R9 | OODA Loop | Fast-moving situation requiring observe-orient-decide-act cycles |
| R10 | PDCA | Iterative improvement; plan a change, try it, check results, adjust |
| R11 | GROW Model | Coaching/goal-oriented; Goal, Reality, Options, Will |

### Scientific & Empirical (R12, R14, R18, R20)
Evidence-driven approaches.

| ID | Method | When to use |
|----|--------|-------------|
| R12 | Scientific Method | Need rigorous hypothesis formation, prediction, and testing |
| R14 | Trial and Error | Solution space is small enough to explore systematically |
| R18 | Hypothesis Testing | Statistical or evidence-based evaluation of specific claims |
| R20 | Sensitivity Analysis | Need to know which variables matter most to the outcome |

### Decision-Making (R13, R15, R16)
Choosing among options.

| ID | Method | When to use |
|----|--------|-------------|
| R13 | MCDA (Multi-Criteria Decision Analysis) | Multiple competing criteria that need to be weighted and scored |
| R15 | Naturalistic Decision-Making | Time-pressured real-world decisions by experienced practitioners |
| R16 | Intuitive Decision-Making | Pattern recognition in familiar domains; expert judgment |

### Comparative & Analogical (R21–R23)
Learning from what's already known.

| ID | Method | When to use |
|----|--------|-------------|
| R21 | Analogical Reasoning | A similar problem in another domain has been solved; transfer the insight |
| R22 | Case-Based Reasoning | Past cases provide templates for current problem |
| R23 | Benchmarking | Comparing against known standards or best practices |

### Scenario & Counterfactual (R24–R27)
Exploring alternative realities and futures.

| ID | Method | When to use |
|----|--------|-------------|
| R24 | Scenario Planning | Multiple plausible futures; need to prepare for uncertainty |
| R25 | Counterfactual Analysis | "What if X had been different?" — understanding causal contribution |
| R26 | Pre-mortem Analysis | Imagining the plan has already failed; working backward to find why |
| R27 | Post-mortem Analysis | Something already happened; structured retrospective |

### Adversarial & Critical (R28–R31)
Stress-testing ideas.

| ID | Method | When to use |
|----|--------|-------------|
| R28 | Red Team/Blue Team | Active adversarial testing of a plan or system |
| R29 | Devil's Advocate | Deliberately arguing against the leading option to find weaknesses |
| R30 | Dialectical Reasoning | Thesis-antithesis-synthesis; resolving contradictions through higher integration |
| R31 | Critical Thinking | Systematic evaluation of arguments, evidence quality, and logical validity |

### Risk & Safety (R32–R35)
Failure analysis and hazard identification.

| ID | Method | When to use |
|----|--------|-------------|
| R32 | FMEA (Failure Modes and Effects Analysis) | Systematically identifying what can fail, how, and what the impact is |
| R33 | Fault Tree Analysis | Working backward from a failure to find root causes (top-down) |
| R34 | Event Tree Analysis | Working forward from an initiating event to find possible outcomes (bottom-up) |
| R35 | Bow-Tie Analysis | Combining fault tree (causes) and event tree (consequences) around a central event |

### Group Methods (R36–R38)
Aggregating multiple perspectives.

| ID | Method | When to use |
|----|--------|-------------|
| R36 | Delphi Method | Expert consensus through iterative anonymous polling |
| R37 | Nominal Group Technique | Structured group brainstorming with voting |
| R38 | Six Thinking Hats | Separating different modes of thinking (facts, emotions, risks, benefits, creativity, process) |

### Optimization (R39–R42)
Quantitative decision support.

| ID | Method | When to use |
|----|--------|-------------|
| R39 | Linear Programming | Optimizing an objective under linear constraints |
| R40 | Decision Trees | Sequential decisions with probabilistic outcomes |
| R41 | Cost-Benefit Analysis | Quantifying and comparing costs against benefits |
| R42 | Trade-off Analysis | Explicitly mapping what's gained and lost with each option |

| ID | Method | When to use |
|----|--------|-------------|

| P9 | Policy Brief | Policymakers; problem, options, recommendation format |

| P11 | Academic Paper | Scholarly audience; lit review, methods, results, discussion |

## 4. Method Selection Decision Trees

### Quick-Path Selection (for when you need to choose fast)

**What kind of problem is this?**

```
Something broke / went wrong
  → Structure: Root cause needs mapping? → S17 (Causal Loops) or S7 (Hierarchy)
  → Reasoning: R4 (Root Cause) or R33 (Fault Tree) or R27 (Post-mortem)
  → Presentation: R8 (Technical Report) or P18 (Causal Diagram)

Strategic decision with competing options
  → Structure: S11 (SWOT) or S16 (Stakeholder Mapping)
  → Reasoning: R13 (MCDA) or R42 (Trade-off) or R41 (Cost-Benefit)
  → Presentation: P17 (Decision Matrix) or P16 (Comparative Table)

Design or create something new
  → Structure: S6 (Systemic Design) or S25 (Problem Framing Canvas)
  → Reasoning: R8 (Design Thinking) or R7 (TRIZ)
  → Presentation: P19 (Flowchart) or P13 (Tutorial) or P23 (Systems Diagram)

Understand a complex system
  → Structure: S1 (DSRP) or S3 (System Dynamics) or S8 (Complex Systems)
  → Reasoning: R12 (Scientific Method) or R3 (Abductive)
  → Presentation: P23 (Systems Diagram) or P10 (White Paper)

Evaluate a plan or proposal
  → Structure: S16 (Stakeholder Mapping) or S14 (PESTLE)
  → Reasoning: R26 (Pre-mortem) or R28 (Red Team) or R32 (FMEA)
  → Presentation: P9 (Policy Brief) or P7 (Executive Summary)

Teach or explain something
  → Structure: S7 (Hierarchy) or S26 (Taxonomy)
  → Reasoning: R21 (Analogical) or R1 (Deductive)
  → Presentation: P13 (Tutorial) or P36 (Metaphorical) or P15 (Dialogue)

Ethical or values-laden question
  → Structure: S5 (Critical Systems) or S23 (Boundary Critique)
  → Reasoning: R30 (Dialectical) or R38 (Six Thinking Hats)
  → Presentation: P15 (Dialogue) or P35 (Dialogue Format) or P33 (Narrative)
```

### Validation

After selecting S + R + P, verify the combination exists in
`01_Areas/SAGE_Methodology/srp_combinations.csv` (4,779 combinations, verified 2026-06-12). Look up by S_ID, R_ID, and P_ID columns.
If the exact combination doesn't exist, pick the nearest valid combination.
Record the Index number for traceability.

### Problem Type and Output Type Cross-Reference

The CSV includes `Problem_Types` and `Output_Types` columns. After selecting methods:
- Check: Does the Problem_Type (simple / complicated / complex / wicked) match your
  problem's actual complexity?
- Check: Does the Output_Type (conceptual / comparative / narrative / qualitative /
  quantitative / sequential / visual) match what you're trying to produce?

Mismatches aren't fatal but they're worth noticing — they might indicate a better method
exists for your specific situation.
