

SRP‑CCC Process Template
## Overview
This template provides step‑by‑step guidance for applying the SRP (Structure → Reasoning → Presentation)
methodology and the CCC   (Compare–Contrast–Consensus) aggregation process. Use it to design answers
that think visibly, leverage multiple methods, and synthesize competing perspectives. The checklists below
support both human and AI agents; tick each item as you complete it.
## Step 1: Structure Phase
Define the problem and context before reasoning. Choose one or more Structure methods to frame the
task, set boundaries, and identify stakeholders.
## Checklist
[ ] Identify the task and audience (e.g., policy question, creative writing, product design). Note the
domain and whether it is safety‑critical.
[ ] Select one or more Structure methods from the list below that suit the task’s complexity and
uncertainty.
[ ] Define boundaries – what is in scope and what is not.
[ ] Identify stakeholders and their goals; map their relationships and levels of influence.
[ ] List constraints and assumptions (e.g., time, budget, legal limits, environment, technology).
Make explicit what must hold true for the analysis.
[ ] Choose system maps or canvases (e.g., stakeholder mapping, causal loops, concept maps) and
sketch high‑level relationships.
[ ] Record any tool calls (such as search queries) used to gather contextual facts. Capture raw
outputs for later citation.
[ ] Write memory entries summarizing key definitions, facts, and design choices for reuse in later
phases.

## Step 2: Reasoning Phase
Explore the framed problem, generate competing hypotheses, and evaluate them. Use diverse Reasoning
methods to reduce bias and reveal blind spots.
## Checklist
[ ] Select reasoning methods appropriate to the problem (see list below).
[ ] Generate at least two rival hypotheses or solution approaches. Write a short statement for
each.
[ ] Gather supporting and contradicting evidence for every rival. Use tool calls (e.g., search,
calculation) to collect data; save raw outputs with timestamps.

[ ] Choose the artifact format (e.g., memo, policy brief, report, narrative) and outline its sections.

[ ] Review for clarity and length; edit to improve readability and flow.

Step 4: CCC Aggregation (Multi‑Perspective Synthesis)
When multiple SRP traces exist, the Compare–Contrast–Consensus process synthesizes them into a single,
robust output.
## Checklist
[ ] Generate multiple SRP traces with different method combinations (ideally 3–5). Ensure each is
complete (Structure, Reasoning, Presentation).
[ ] Score each trace on evidence quality, methodological fit, risk coverage, and audience
appropriateness.
[ ] Compare: Note where the traces agree and where they diverge. Highlight complementary
insights.
[ ] Contrast: Identify why differences exist (assumptions, evidence weight, stakeholder priorities).
Use critical and dialectical reasoning.
[ ] Consensus: Combine the strongest elements of each trace into a single answer. Clearly explain
the synthesis logic.
[ ] Preserve dissent: Document unresolved conflicts and the conditions under which each dissenting
view would become valid.
[ ] Propose next tests to resolve outstanding uncertainties or to decide between alternatives.
[ ] Record the final artifact and append the raw traces, dissent rationale, and proposed tests for
transparency.

## Appendix: Using This Template
Plan ahead. Before starting, decide how many SRP traces you will run and which S/R/P methods are
appropriate for the task. Use the method lists to ensure diversity.
Document everything. Capture tool inputs and outputs, memory writes, and reviewer notes.
Transparency enables reproducibility and prevents hallucination.
Iterate and refine. Use the kill‑steps to stop early if an approach fails. Revise the trace or adjust
method selection before investing more effort.
Adapt responsibly. The lists provided are comprehensive but not exhaustive. Add domain‑specific
methods as needed, but always record their rationale and compatibility.
This checklist‑driven template is designed to make the SRP and CCC processes repeatable and auditable for
both humans and AI agents. When used consistently, it encourages structured thinking, plural reasoning,
and clear communication.
